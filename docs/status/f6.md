# F6 status — developer experience

Updated: 2026-07-17

Status: **strict CLI/process API candidate, polling source watch, and local PliegoRS browser reload

## Implemented

- [x] `pliego-cssc compile` and its `build` alias generate deterministic CSS with `minified`
  compatibility-default and Lightning CSS-backed `pretty` profiles.
- [x] `pliego-cssc bundle` consumes a schema-1/schema-2 plan, snapshots one shared theme/source revision,
  compiles named explicit source partitions before publication, and emits independent schema-3
  CSS/manifest pairs through one rollback-capable publication group; `--check` verifies exact bytes.
- [x] `check` runs extraction, theme validation, lowering, composition, emission, and Lightning CSS
  entirely in memory.
- [x] `inspect` schema 2 emits deterministic JSON with all three identity-format versions, the active
  theme, format, exact CSS digest/length, findings, origins, and semantic style identities.
- [x] Explicit `--style`, semantic `--compose`, line-oriented `--input`, and repeatable Rust
  `--source` file/directory inputs can be combined.
- [x] Rust directory expansion is lexical, skips symlinks, hidden directories, `.git`, and `target`,
  and deduplicates canonical file paths.
- [x] Theme selection supports mutually exclusive `--config`, `--seed`, or explicit DTCG
  `--tokens`; only `pliego.theme.toml` uses fail-closed discovery near supplied inputs/packages.
- [x] Cargo `theme!` preserves its TOML form and accepts
  `tokens = FILE, inputs = { "modifier" => "context" }` once per package. Empty inputs use
  Resolver defaults, duplicates fail closed, and CSS generation must repeat the same selection.
  The full Debian WSL2 workspace/MSRV/API gates and the Windows dirty-package DTCG/TOML consumers
  pass; commit `9714b09` also passes the clean Debian WSL2 package gate.
- [x] Watch mode polls line-oriented input, Rust files or directory trees, and the resolved explicit
  or discovered TOML/Resolver document every 100 ms.
- [x] Every poll captures one exact-byte immutable snapshot; change detection and compilation use
  the same input, source-tree, and resolved-theme bytes instead of rereading mutable files.
- [x] Added, removed, renamed, or changed Rust files trigger recompilation without relying on mtime
  or a truncated content fingerprint.
- [x] Parsed Rust units and scanner failures are cached by canonical path, logical provenance path,
  and exact bytes; a source edit reparses only misses and a theme edit reuses syntax reports while
  rerunning theme-dependent semantic validation.
- [x] Successfully resolved source candidates are cached per file and `themeId`; unchanged units
  avoid parsing and lowering, while a theme change invalidates semantic IR without invalidating scans.
- [x] A changed snapshot must be identical across two consecutive polls before compilation, avoiding
  publication of a transient valid prefix during truncate-and-rewrite editor saves.
- [x] A warm-vs-cold oracle covers edit, create, rename, delete, invalid-source recovery, token
  invalidation, and equal-length source/theme mutations; a separate regression proves snapshot
  compilation never rereads a subsequently mutated file.
- [x] A compilation failure does not publish the invalid artifact; a write failure is retried without
  requiring another input change.
- [x] Output publication is byte-aware: unchanged CSS/manifest destinations retain their existing
  files and modification times, avoiding redundant downstream rebuild signals.
- [x] Changed CSS/manifest destinations publish as a recoverable group: an injected second-rename
  failure with a successful rollback restores the previous pair, and the equivalent new-pair test
  leaves no destinations or temporary/backup debris. Rollback failures remain explicit errors.
- [x] Publication acquires advisory locks for every canonical physical parent plus stable final
  destination name in deterministic order; a backup rename cannot change lock identity, and a
  second cooperating writer fails before backup or mutation.
- [x] Schema-3 manifests expose all three identity-format versions, deterministic source origins plus
  `themeId`, target contract, output format, `cssSha256`, and `cssBytes` for tooling and
  artifact-integrity checks.
- [x] Compile, watch, and bundle support explicit manifest schema 4 plus strict reachability schema
  1. The graph connects adapter-attested routes/islands, compiler-verified exact component sites,
  canonical semantic declarations, and direct tokens while default schema-3 bytes and CSS remain
  unchanged.
- [x] The same commands support manifest schema 5 / graph schema 2 with exact final rule/declaration
  ranges, many-to-many lineage, generated-output markers, and fail-closed complete physical coverage;
  schema-3/schema-4 JSON and CSS compatibility vectors remain unchanged.
- [x] Watch snapshots include requested reachability bytes; a graph-only change can republish only
  the manifest because CSS publication remains byte-aware.
- [x] Output path validation rejects aliases with inputs, sources, explicit configuration, the
  resolved auto-discovered theme, and the second output artifact.
- [x] `pliego-cssc catalog` emits deterministic Markdown/JSON, supports byte-exact `--check`, and
  protects its resolved theme input from output aliasing.
- [x] Catalog JSON schema 3 exposes exact compiler `matchName` metadata and all three identity-format
  versions for completion, while `pliego-cssc explain --format json` schema 2 resolves a style into
  theme/style identity, pretty CSS, and ranged per-utility descriptors for hover tooling.
- [x] `pliego-cssc fmt` exposes the parser's idempotent canonical printer for explicit styles and
  line-oriented documents, with exact `--check` and non-aliasing `--output`; `check` remains the
  theme-aware semantic linter.
- [x] Read-only `fmt --source ... --check` reports `FMT001` with exact ranges and replacements for
  `pc!`, `pcx!` bases, and every statically visible branch without rewriting Rust.
- [x] Opt-in `fmt --source ... --apply` replaces only complete Rust literal tokens after exact
  snapshots, non-overlap checks, full-document reparse/rescan, advisory locks, and a second snapshot
  check. Multi-file publication preserves permissions and is rollback-capable; stale inputs fail
  before any write. It does not claim crash-atomicity against process or machine termination.
- [x] One-shot commands accept global `--diagnostic-format json` and emit one schema-1 stderr
  document with ordered PCS, PSC, PCX003, or FMT001 findings; PCL001/PCL002 cover invocation and
  untyped tool failures without contaminating stdout.
- [x] Single-value command options are strictly single-use across compile/check/inspect, watch,
  catalog, explain, bundle, and formatting surfaces; a duplicate fails even when it repeats the
  same value. Only explicitly repeatable inputs such as `--style`, `--source`, and `--compose` may
  occur more than once.
- [x] The minimal application/build and one-shot process API candidate is documented and exercised
  by `pnpm check:api`. Its external Rust 1.85 smoke checks `Style`/`StyleId`, `pc!`, `pcx!`, a renamed
  facade dependency, both unit-returning TOML and DTCG `theme!` forms, standalone-CWD CLI use,
  Rust/CLI DTCG selection and identity agreement, CSS/manifest integrity, manifest schemas 3/4,
  inspection/catalog/explain schemas
  2/3/2, graph/reachability schema 1, identity formats 2/1/1, and fail-closed duplicate options. The
  same command then runs the graph and physical-trace gates, covering manifest schema 5, graph schema
  2, physical ID formats 1, exact graph-1 projection, ranges, and fail-closed reconciliation.
- [x] The pinned `pliego-cssc watch` + `pliego dev` gate alternates 20 valid `pc!` edits, verifies
  semantic padding, exact served/published CSS hashes, stale-class removal, and exactly one stable
  SSE generation per edit, then records CSS and site/SSE convergence p50/p95. Invalid input and the
  tested unchanged CSS/manifest group preserve the last valid publication without advancing reload.
  A controlled local Chromium replay separately observed class `pc_89r...`/16 px change to
  `pc_7ru...`/24 px without manual navigation; it is not part of the automated latency measurement.
  PliegoRS ignores the compiler's reserved publication coordination files and waits for a stable
  publication group before rebuilding.

## Current watch boundary

Watch by itself is an artifact-regeneration loop. Composed with the pinned `pliego dev`, it now has
a certified full-page browser reload path through PliegoRS's SSE endpoint. PliegoCSS does not emit a
WebSocket event, control a dev server, or patch a stylesheet in a running page. The watch command
can import explicit route/island ownership from a framework sidecar but does not invoke the pinned
application adapter that derives topology from PliegoRS's registry and exact Cargo inventory.
Declarative bundle plans are one-shot and explicit; they are not a route-aware watch mode.

The ordinary Rust edit now reaches a local browser with measured latency and source-cache reuse. F6
remains open for complete CLI/LSP diagnostic-equality coverage, hosted editor and multi-browser
evidence, and RC activation.
CSS-only HMR and fragment-level emission remain explicit optimizations, not claims of the current
full-page reload loop.
