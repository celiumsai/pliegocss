## Gate result

The F1 gate is closed. A literal such as `pc!("flex items-center gap-4")` reaches validated semantic
IR while the procedural macro is expanding. Invalid utilities, value domains, conflicts, negative
forms, and variant chains fail the Rust build with a `PCS` diagnostic. Equivalent utility order and
commuting variant order produce the same nonzero `StyleId`.

## Compatibility boundary

`StyleId` uses the machine-enforced format-2 candidate. It encodes normalized assignments and the
active theme as explicit tagged bytes rather than Rust `Debug` strings, then uses the first 128 bits
of SHA-256 in big-endian order. Class-name format 1 encodes that result as `pc_` plus lowercase base
36. Exact golden vectors are frozen at workspace version `0.0.0`; approving them as a published
SemVer contract remains a release decision. See the
[StyleId format-2 reference](../reference/style-id-format-v2.md).

Persistence uses a separate [semantic IR binary format 2](../reference/semantic-ir-binary-v2.md).
It retains assignment spans and can reconstruct validated IR under the exact active theme; it does
not reuse Rust enum layout or claim that the internal `SemanticStyle` type itself is a public wire
DTO.

## Deferred hardening

- Initial parser fuzzing and broader snapshot coverage remain open from the week-one plan.
- The seed catalog is intentionally narrow; catalog completeness belongs to F2 and later fixture
  work.
- The public `Style` facade retains only `StyleId`; utility source text stays host-side and does not
  become runtime style state.
