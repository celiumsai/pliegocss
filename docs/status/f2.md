## Current scope and debt

The core API emits one semantic style at a time; `pliego-cssc` aggregates and deduplicates complete
styles by identity before Lightning CSS validation and target transforms. Lowering and emission use
the active typed registry, and user token values and breakpoints are validated before entering it.

The remaining boundary is application knowledge. Static scanning includes every `.rs` file under
an explicitly supplied source directory and does not resolve Cargo modules, routes, islands, feature
flags, or runtime reachability. Default schema 3 preserves source origins; opt-in schemas 4/5 import a
complete component/route/island graph from a framework-owned sidecar but do not derive it. The
separate `--prune-unreachable` flag can remove whole unreachable StyleId rule sets from that explicit
graph; it does not prune theme variables. Schema 5 additionally traces the exact final CSS. Normal
CSS remains necessary for the platform's long tail.

## Gate state

Gate A and Gate B are closed as conditional GO decisions over their matched fixtures. They validate
continued engineering, not production readiness. F2 remains open for RC activation of the selected
API, multi-browser validation, automatic application collection, token pruning, and
cross-platform reproducibility.
