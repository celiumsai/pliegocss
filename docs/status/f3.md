- [x] The CLI accepts explicit styles, compositions, line-oriented input, and visible `pc!`/`pcx!`

## Current architecture boundary

The procedural macros parse and lower visible literals during Rust compilation, then return an
ID-only `Style`. They do not run Lightning CSS or write stylesheets. The CSS pipeline consumes
explicit styles or supplied source paths, emits deterministic rules, and invokes Lightning CSS
afterward. Static source scanning parses Rust syntax; directory traversal includes every discovered
Rust file and does not execute code or perform semantic Cargo reachability analysis.

Theme TOML and DTCG Resolver selection are also build-only. `pliego-css-config` normalizes and
validates the source; `pliego-css-build` serializes only the active registry; `pc!`/`pcx!` decode
that canonical artifact; and the registry-aware emitter requires the same theme identity. A
controlled CLI build separately publishes the complete Resolver graph. No theme parser, semantic
IR, or styling runtime is shipped in browser WASM.

CLI artifact publication is staged per file and committed as a rollback-capable group under advisory
destination locks. Existing destinations move to sibling backups before prepared files are renamed;
reported failures in the same process attempt to restore prior destinations or remove new ones, and
surface rollback failures explicitly. This is not one filesystem transaction: a crash or external
reader between renames can still observe missing or mixed paths, so consumers must verify the manifest
digest and byte length.

F3 is therefore sufficiently implemented to support the conditional viability gates, but it is not
closed as a production pipeline. F5 PliegoRS integration and the remaining F6 development
experience work are not declared complete here.
