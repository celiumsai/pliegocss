## Reproducibility boundary

`integration-tests/pliegors-smoke` is intentionally outside the PliegoCSS workspace. The full harness
expects `PliegoCSS` and `pliegors` as sibling directories, runs Cargo with Rust 1.85 and `--locked`,
and refuses to run after unreviewed revision or covered-source drift. Normal repository CI cannot run
this gate without provisioning the sibling closed-IP checkout.

The client-enabled path additionally requires `wasm32-unknown-unknown` for the exact Rust toolchain
and `wasm-bindgen 0.2.126`. The CLI tool may be built with a newer host Rust compiler while the
application client remains compiled with Rust 1.85.

The covered sibling sources pass Rust 1.85 with the fixture lockfile, including `pliego-ssg` and its
pinned `cap-std`/`cap-fs-ext` dependencies. `pliego-macros`, `pliego-resume`, and `pliego-ssg` are all
tracked by the pinned clean PliegoRS revision, so the audited source boundary is reconstructible from
a clean clone.

Together, the integration and browser gates prove bounded deterministic product-registry collection,
complete visible-macro ownership, DOM/view/builder SSR, verified deterministic SSG publication,
adapter-derived source partitioning, schema-5 pruning, asset-plan-driven route/island bundle
isolation, deliberate dead-bundle exclusion, asset integrity, and one real Chromium resumability
event with DOM identity preservation while one measured WASM client starts exactly once. Cargo
source completeness is limited to the three exact built targets and configuration. These gates are
not evidence for unbuilt feature permutations, universal preload performance, hosted or
multi-browser behavior, crash-atomic publication, or a complete production application.
