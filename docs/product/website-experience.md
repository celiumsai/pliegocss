# PliegoCSS website experience

**Status:** implementation contract  
**Audience:** product, brand, documentation, and engineering contributors  
**Release boundary:** the site may be built and verified before the product is
released; publication remains a separate authorized operation

## Product bar

The website is not a brochure around the compiler. It is the first useful
PliegoCSS product surface.

A visitor must be able to understand the differentiated contract, manipulate
real compiler-backed examples, inspect the resulting CSS and evidence, find a
specific utility or command, and move into the documentation without losing
context. Visual quality earns attention; working interactions earn trust.

The experience is evaluated against the strongest developer-tool websites,
including the current Tailwind CSS product and documentation, without copying
their visual system or claiming feature parity.

## Live reference audit

The July 20, 2026 review of `tailwindcss.com` found a product surface with:

- a long-form homepage that alternates narrative, code, and working previews;
- interactive responsive, filter, color, grid, easing, direction, and dark-mode
  demonstrations;
- a global command search;
- a dense, categorized documentation tree;
- embedded examples inside feature reference pages;
- clear paths to documentation, playground, components, templates, learning,
  and community.

The first PliegoCSS site draft had a real build pipeline, strong typography,
correct brand tokens, and build-time compiler recipes. It still failed the
product bar because most sections were explanatory cards, the playground only
switched four static examples, the Three.js scene was ambient, and the
documentation exposed too little of the actual catalog.

Passing build and browser checks did not make that draft competitive.

## Differentiated concept: Cascade Laboratory

PliegoCSS should not imitate Tailwind's abundance of visual utility demos. Its
own advantage is that authored intent can remain connected to a stable
identity, emitted CSS, physical declarations, diagnostics, and reproducible
evidence.

The site therefore behaves as a **Cascade Laboratory**:

1. **Author** — select or edit visible utility intent.
2. **Resolve** — see conflicts, variants, and semantic ownership.
3. **Emit** — inspect the exact CSS generated by the repository compiler.
4. **Trace** — follow identity, byte count, hash, and physical effect.
5. **Adopt** — continue into audit, migration, integrations, or reference docs.

No browser demo may claim to compile arbitrary input if it uses a JavaScript
approximation. Interactive examples use a build-time corpus generated by the
actual `pliego-cssc` binary and disclose that boundary.

## Required product surfaces

### Global frame and public-preview identity

- Follow the ordered PliegoRS information frame without copying its visual
  identity: compact product masthead, explicit status rail, primary content,
  directory footer, then ownership rail.
- The status rail reads `PUBLIC PREVIEW / MEDELLÍN / 2026`.
- The footer states that PliegoCSS is an independent Celiums Solutions LLC
  project, includes `© 2026 Celiums Solutions LLC`, credits Medellín, and names
  Apache-2.0.
- English lives at the route root. Spanish lives at the equivalent `/es/`
  route. Every page must expose `en`, `es`, and `x-default` alternates.

### Homepage

- A fast, unmistakable statement of the product contract.
- A useful compiler console visible in the first viewport.
- A responsive component theatre with direct manipulation.
- A semantic conflict demonstration with a real PCS diagnostic.
- A source-to-output-to-evidence narrative driven by the same generated data.
- Proof that distinguishes measured, inherited, pending, and uncertain.
- Clear routes to Playground, documentation, utility catalog, and adoption.

### Playground

- Search and insert supported catalog examples.
- Compose a bounded recipe from real precompiled combinations.
- Show exact utility input, stable class, emitted CSS, hash, byte count, and
  utility explanations.
- Include deterministic reset, copy actions, keyboard operation, loading,
  unsupported-input, and failure states.
- Explain why arbitrary online compilation is not being simulated.

### Documentation

- Persistent category navigation on reference pages.
- Global command search with keyboard shortcut.
- Generated utility catalog from `pliego-cssc catalog`.
- Reference paths for authoring, CLI, analysis, evidence, migration,
  integrations, policies, and troubleshooting.
- Copyable examples and an on-page table of contents.
- Mobile navigation that does not hide the information architecture.

### Examples

- At least three visually distinct product examples that use the shipped CSS
  and expose their relevant style recipe.
- Responsive controls that change the stage width rather than replacing it
  with a static screenshot.
- No generic dashboard template as the sole expression of the system.

### Legal and accessibility

- Publish equivalent English and Spanish routes for the legal register, terms,
  privacy, cookies/storage, acceptable use, and accessibility.
- Legal copy remains narrow and factual. It does not invent a jurisdiction,
  certification, SLA, warranty, or provider behavior.
- The current static build does not write cookies, `localStorage`, or
  `sessionStorage`; any future change must update the policy before activation.
- Language switching uses URLs and does not persist an identifier.

## Visual direction

The visual system uses the brand's fold and cascade rail as information
architecture:

- **Carbon** is the authored/source environment.
- **Paper** is the reading and documentation environment.
- **Cobalt** is compiled output and selected action.
- **Cyan** is lineage, focus, and live trace.
- **Coral** and **Amber** remain diagnostic colors only.

Sections should change spatial mode rather than repeat cards on one dark grid.
The homepage alternates a cinematic Carbon laboratory, a bright Paper
workbench, a saturated Cobalt compilation field, and restrained evidence
surfaces. Typography, fold geometry, generated imagery, UI controls, and
motion must all use the same system.

## Motion contract

- GSAP drives finite narrative transitions and compiler-state interpolation.
- ScrollTrigger may pin one compiler story only when the native reading order
  remains intact.
- Lenis is enhancement only; keyboard, anchor, and reduced-motion behavior stay
  native.
- Three.js must expose selectable compiler layers or causal state, not merely
  decorate the hero.
- Motion stops or degrades when the page is hidden, Save-Data is enabled, WebGL
  is unavailable, or reduced motion is requested.

## Generated image system

GPT Image 2 assets, when the approved generation channel is available, use the
prompt contracts in `brand/image-prompts/`. They must:

- visualize folded material, physical cascade layers, evidence envelopes, and
  macro engineered surfaces;
- leave deliberate negative space for responsive layouts;
- contain no generated text, fake UI, logos, watermarks, or generic neon
  developer imagery;
- be art-directed in the PliegoCSS palette without recoloring the logo;
- ship with responsive derivatives and explicit alt text or a decorative role.

Generated imagery is supporting editorial matter. Interactive product truth
continues to come from real compiler artifacts.

The reviewed six-image collection is now committed under `brand/images/` with
PNG masters and AVIF/WebP delivery derivatives. The hero uses the cascade
chamber; the evidence section uses the archive; the brand page preserves the
full semantic-fold and material-study system.

## Quality gates

The site is not ready until the current source proves:

- every route builds through PliegoRS;
- site styles build through PliegoCSS and bind to a manifest hash;
- the lab corpus is generated by the current `pliego-cssc`;
- keyboard, focus, reduced motion, Save-Data, and no-WebGL paths work;
- there are no browser console errors or broken internal links;
- responsive layouts are checked at phone, tablet, laptop, and wide desktop;
- interactive controls change observable output and reset deterministically;
- asset, JavaScript, font, and image budgets are enforced;
- the globally loaded `site.js` entry remains below 64 KiB gzip; Three.js is
  split into a lazy route-level chunk instead of taxing every documentation
  and legal page;
- all English and Spanish routes, canonical URLs, language alternates, sitemap
  entries, legal links, and client-rendered strings stay in parity;
- the rendered experience passes a deliberate visual review, not only DOM
  assertions.

## Evidence language

All metrics and release statements use the repository evidence vocabulary:

- **Measured** — reproduced for the identified current source.
- **Inherited** — valid prior evidence with limited authority.
- **Pending** — required but not yet run or published.
- **Uncertain** — insufficient evidence.

The website must never turn a private tag, local pass, or attractive demo into
a public release claim.

### Cloudflare publication boundary

The generated output is a Workers Static Assets unit declared by
`site/wrangler.jsonc`. Production serves only the `pliegocss.dev` custom
domain; `workers.dev` and preview URLs are disabled. The generated `_headers`
file establishes the CSP, framing, MIME-sniffing, referrer, feature,
cross-origin, HSTS, and cache contracts at the edge.

`pnpm check:site-deployment` runs Wrangler in `--dry-run` mode. It proves that
the current generated output and deployment profile are accepted locally; it
does not prove that DNS is connected or that a production deployment exists.
Those remain explicit release operations requiring authorization.

The public-preview production deployment was authorized and completed on
2026-07-21. Cloudflare Worker `pliegocss-site` version
`2a406393-bcfc-4c73-87ca-761e047fa390` is attached to the
`https://pliegocss.dev` custom domain with Worker-managed apex DNS and active
edge certificates. Production response replay covers English, Spanish,
documentation, legal, playground, security.txt, 404, CSP/security headers, and
immutable-asset caching; local dry-run evidence remains distinct from this
production evidence.
