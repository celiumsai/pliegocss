# Reachability-pruning benchmark

Date: 2026-07-13

Status: deterministic change gate for the opt-in application-union pruning contract

This benchmark isolates what `--prune-unreachable` does when a trusted reachability-schema-1
sidecar marks only part of a scanned source snapshot as reachable. It is a deliberately controlled
payload, not a representative application sample and not evidence of a universal percentage
reduction.

## Fixture and method

The harness creates a temporary, byte-deterministic Rust source and sidecar. The source contains 14
distinct `pc!` sites:

- one component referenced by route `home`;
- one component referenced by island `counter`; and
- twelve declared components referenced by no route or island.

The twelve dead sites use real multi-utility styles from the existing fixture vocabulary. Their
large share of this synthetic input makes the percentage reduction intentionally unsuitable for a
product-size claim.

The harness runs four schema-5 compilations against the same generated bytes:

1. baseline A without pruning;
2. baseline B without pruning;
3. pruned A with `--prune-unreachable`; and
4. pruned B with `--prune-unreachable`.

Each repeated pair must produce byte-identical CSS and manifest files. Both manifests must retain
valid CSS hashes and byte counts and a closed graph-schema-2 projection. The gate checks canonical
node/edge order, global node identity, exact source ranges, non-dangling endpoints, component
ownership for every semantic declaration, physical contribution for every semantic declaration,
one rule owner for every physical declaration, and a semantic or synthetic cause for every
physical declaration.

It also fails independently if raw or gzip output stops getting smaller, even if someone updates a
reviewed hash.

## Scope boundary

The benchmark proves only whole-style removal under the current union of declared route and island
roots. It does not measure route-specific loading, shared extraction, critical CSS, runtime latency,
or a complete PliegoRS application.

Theme emission is intentionally disabled. The reduction from 30 to 9 token nodes describes the
semantic manifest graph after dead declarations disappear. It does **not** prove pruning of the
registry-backed custom properties emitted by `--theme`; arbitrary CSS can still reference those
properties, so token-theme pruning remains a separate problem.

## Running the gate

Use the exact reviewed check:

```console
pnpm check:pruning
```

Run the harness without `--check` to print a current machine report without weakening the frozen
contract:

```console
node scripts/measure-reachability-pruning.mjs
```

The script requires Node 22.13 or newer. It uses `PLIEGO_CSSC` when provided; otherwise it uses the
portable `target/debug/pliego-cssc` executable and builds that target with Rust 1.96 only when it is
missing. CI supplies its already-built matrix executable. Temporary inputs and artifacts live only
under `target/benchmarks/reachability-pruning/run-<pid>`; the harness validates that containment
before deleting the directory on exit.

The executable harness is
[`scripts/measure-reachability-pruning.mjs`](../../scripts/measure-reachability-pruning.mjs).
